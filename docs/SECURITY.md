# Security Design

The 0.2 implementation adds a CLI-issued setup token, Argon2id passwords, revocable sessions, a fixed admin origin, CSRF tokens, and scoped API keys. The remaining controls in this guide are release requirements. See the [project status](PROJECT_STATUS.md) and [threat model](THREAT_MODEL.md) for verification and acceptance criteria.

## 0.2 deployment boundary

- Set `ADMIN_ORIGIN` to the browser-visible origin. The default is `http://localhost:8081`. Plain HTTP origins are accepted only for loopback. A reverse proxy must preserve the configured Host and port, and only that proxy should connect to the cleartext admin backend. A request with any other address gets `404`. Outside `/api/` it carries a static English or German page without scripts that says to open the configured administration address. The page names no address, host, product, or version. Only the first mismatch per process is logged with the expected origin.
- Use a dedicated admin hostname for cookie isolation. A cookie applies to every port on its host. HTTPS sessions use a host-only `__Host-shortcircuit_session` cookie with `Secure`, `HttpOnly`, `SameSite=Strict` and `Path=/`. Loopback HTTP uses a separate cookie name.
- Setup, sign-in, recovery, and password changes share a bounded attempt budget of eight requests per peer and 60 per process per minute. The budget uses the TCP peer. Hosts behind one reverse proxy share its peer budget.
- Browser writes require the configured Origin and `X-CSRF-Token`. Authentication entry points require the configured Origin. The bearer API uses scoped keys without session cookies. Only active browser sessions can manage keys.
- The local CLI prints a short-lived one-time setup or recovery token. Treat this terminal output as a secret. Password changes and recovery revoke existing sessions and establish a new session. Review API keys separately after recovery.

## Proposed Defaults

| Area | Default |
| --- | --- |
| Network | Use separate public and admin listeners. The public listener accepts only configured hosts. Restrict admin access to the LAN or VPN through the proxy where possible. Explicitly configure trusted proxy peers and keep CORS disabled in normal operation. |
| Access | Disable public registration and default credentials. Bootstrap setup locally. Require authentication and the appropriate role or scope for link creation, exports, and configuration changes. |
| Links | Use 302 for new links with editable destinations. Enable query forwarding, extra paths, permanent redirects, and fallbacks explicitly. Keep internal diagnostics private. |
| Outbound requests | Disable monitoring, title and favicon retrieval, webhooks, and external integrations by default. Apply a central fetch policy to any enabled feature. |
| Analytics | Collect minimal data and apply defined retention periods. Public redirects use no analytics cookies. See [privacy and analytics](PRIVACY.md). |
| Application data | Run as a non-root user with restrictive file permissions. Drop capabilities, leave the Docker socket unmounted, and use a read-only root filesystem where supported. Allow writes only under `/data`. SQLite temporary files use `/data/tmp` (`SQLITE_TMPDIR`), created with mode 0700. |
| Restore | Require reauthentication for downloads and restores. Enforce upload quotas, validate in isolation, schedule maintenance, and retain a rollback dataset. Pause integrations and review credentials after a restore. Snapshots from older schemas, back to schema 6, must match the embedded migration history and its schema exactly. Only the embedded migrations then upgrade a private staged copy, never the uploaded file or the live database, and the result must match the current schema before activation. |
| Extensions | Require explicit configuration and path collision checks for same-domain operation, additional roles, public QR routes, and custom landing pages. |

## Admin Access, Sessions, and API Keys

- Generate a cryptographically random 256-bit setup token through the local CLI, with a proposed lifetime of 15 minutes. Display it directly in the trusted terminal and enter it in a secret field. Store only its digest. Create the administrator, consume the token, and update the setup status in a single transaction. Rate-limit failed attempts and keep the token out of logs, URLs, and persistent environment entries.
- Restrict recovery to operators with host access and the controlled local CLI. Audit and validate recovery and revoke existing sessions on completion. Support explicit revocation and rotation of access keys. Require recent authentication for password and key changes in the admin interface.
- Use Argon2id with a random salt per password and store the encoded PHC string. Rehash when parameters increase. Start with the OWASP minimum of 19 MiB, two iterations, and parallelism of one. Benchmark on the target hardware, run key derivation off the async executor, and initially allow at most two concurrent derivations per instance. Apply distinct request limits to admin sign-in and link passwords under a shared resource budget. [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
- Make sessions revocable on the server. Put a random token in the cookie and store its digest in the database. Rotate the token at sign-in and when permissions change. Revoke affected sessions at sign-out, password change, or recovery. The proposed idle timeout is 30 minutes and the absolute timeout is 12 hours. Set a host-bound `__Host-` cookie with `Secure`, `HttpOnly`, `Path=/`, and `SameSite=Strict` on the HTTPS admin origin. Reserve cleartext admin access for local development and bootstrap. Require HTTPS for regular admin access. [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)
- Require a session, a valid synchronizer CSRF token, and a validated Origin for browser writes. Keep GET free of API mutations. Check Origin, Host, Content-Type, and request rate during setup and sign-in. Protected public links bind a five-minute signed form value to the configured origin, exact request path and query, link ID, and protection revision. Password verification uses bounded Argon2id workers and rate limits by TCP peer. Use the reverse proxy for finer limits when visitors share its peer address. [OWASP CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)
- Serve protected links over HTTPS, with HTTP loopback access for local development. Explicit confirmation leaves a one-time link available to visitors after GET and HEAD previews. A successful POST redirects with `303`, which instructs the browser to continue with GET. Published clients may retain permanent responses from earlier configurations. Issue a new short URL for restricted access if the previous URL already used a permanent redirect.
- Use an authenticated browser session to read and export historical destinations. Apply the standard origin and CSRF checks to restore and purge. Restore metadata or redirect policy through the current validation rules and preserve passwords, one-time consumption, and visit counters. Protection events exclude password material and record only the actor, timestamp, and action.
- Bulk actions require a browser session, Origin validation and CSRF. The service validates every selected link within its transaction using the link's numeric ID and selection key. Permanent deletion requires explicit confirmation. The structured deletion log includes the count and excludes link data.
- Use a lookup ID and a 256-bit secret for each API key. Store the name, expiration, scopes, and domain metadata separately from the secret digest. Use a standard hash suitable for high-entropy tokens, compare digests in constant time, and use a distinct digest context for each token type. Display the secret once and provide a rotation procedure. The API uses bearer authentication. Define the applicable authentication method per route and reject conflicting session and API key credentials.
- Check permissions centrally for the requested action and object. Start with one local administrator and API scopes for reading, creating and editing, deleting, and reading analytics reports, with an optional domain scope. The implemented `analytics` scope covers only the summary and report download. It applies the key's host restriction inside every report query and omits the instance-wide dropped-event counter for host-bound keys. Analytics settings, visit details, and deletion stay restricted to browser sessions. A link-scoped `read` key can read one link with `GET /api/v1/links/{id}` within its host, but the response omits redirect counts and the daily trend unless the key also holds the `analytics` scope. A per-link summary resolves the link inside the key's host and returns `404` for any other link. Give export, restore, integration, and key management their own privileged actions. Restrict queries and writes to authorized objects.

## Outbound Requests and SSRF Prevention

1. Validate URLs and ports centrally. Allow approved schemes and only public ports 80 and 443 for general fetching. Derive the HTTP Host, TLS server name, and domain policy from the validated URL. Reject user information in URLs and avoid applying DNS search suffixes to untrusted names. Block internal listeners, container and host networks, and special-use addresses. Classify IPv4-mapped IPv6 addresses consistently. Use the IANA registries and account for environment-specific reservations, link-local, unique-local, loopback, metadata, multicast, NAT translation, and transition ranges. [IANA IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry/) · [IANA IPv6](https://www.iana.org/assignments/iana-ipv6-special-registry/)
2. Resolve DNS under a deadline and validate every A and AAAA candidate. Reject mixed sets of allowed and blocked addresses. Open sockets only to validated addresses. Retain the validated origin hostname for the HTTP Host and TLS server name and verify certificates normally. The first prototype will verify whether Reqwest can enforce these rules with a restricted resolver and connection pool. Reuse connections only when the policy and validated connection identity match. Disable environment-configured proxies, cross-host pooling, the cookie store, and outbound referrers for these requests. [OWASP SSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html) · [Reqwest ClientBuilder](https://docs.rs/reqwest/latest/reqwest/struct.ClientBuilder.html)
3. Disable automatic redirects. Revalidate each public health monitoring hop before connecting. Apply separate connect, read, and total timeouts, starting at 2, 3, and 8 seconds respectively, with at most three hops per job. Limit streaming reads before and after any decompression. Disable transparent decompression for standard requests and set an explicit expansion budget for approved exceptions. Limit header and URL sizes, with an initial 16 KiB header limit and a 128 KiB sample for title retrieval. Read response bodies only as needed and within the applicable limits.
4. Apply a privileged connector policy that specifies the exact origin, port, purpose, and allowed address range for each internal connector. Send credentials only to the configured, validated HTTPS destination with automatic redirects disabled. Configure a private CA when required. Use an offline file for an import when suitable HTTPS is unavailable. Approve internal webhooks for a specific host and port.
5. Bound overall concurrency with a global semaphore and enforce a small per-destination concurrency limit. Supplement application controls with restricted network exposure, host egress rules where applicable, and observable block reasons. A link redirect is browser navigation and consumes no server-side outbound request budget.

## Additional Hardening

- Configure trusted proxy peers explicitly for IPv4 and IPv6. Evaluate incoming forwarding information from the immediate peer to the nearest trust boundary. Ignore forwarding headers on direct requests from untrusted peers and have the proxy set origin headers itself. Read the admin origin and public base URLs from configuration.
- Restrict the admin CSP to required local origins, block untrusted inline scripts, and disallow framing with `frame-ancestors 'none'`. The implemented admin policy is `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; font-src 'self'; manifest-src 'self'; connect-src 'self'; frame-src 'self'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'`. `frame-src 'self'` exists only for the sandboxed public page preview. Set `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, and a restrictive `Permissions-Policy`. Enable HSTS after confirming the HTTPS strategy, with separate decisions for `includeSubDomains` and `preload`. Use `Cache-Control: no-store` for responses containing secrets or dependent on application state. [OWASP Secure Headers Project](https://owasp.org/www-project-secure-headers/)
- Validate URLs, Unicode, and paths before storing them and again before writing headers. Parse the expected JSON fields, use parameterized SQL, and render typed values through text bindings. Preserve the wire format of signed destination URLs and require manual confirmation for changes. See the [architecture](ARCHITECTURE.md).
- Apply low limits to sign-in, setup, recovery, and link unlock attempts by IP or network and by account or link. Use exponential backoff and shared ceilings. Apply separate API quotas per key and for writes. Set generous global and per-host connection and request budgets on the public listener, additional limits for lookup misses, and bounded rate-limit bucket maps. Return 429 with suitable retry information when a limit is exceeded. Use temporary backoff to prevent an attacker from imposing a permanent account lockout. Tune thresholds after lab and proxy testing.
- Limit uploads by permission, size, file type, and decoding cost. Decode image assets and store them in approved raster formats. Generate SVGs from controlled drawing data. Reject disallowed restore archive paths, links, unexpected entries, and resource overruns. Protect CSV exports against spreadsheet formula execution. [OWASP File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)
- The QR logo endpoint requires an administrator browser session, Origin and CSRF validation. It accepts a raw static PNG of at most 256 KiB and 512 pixels per side. Two upload slots apply an eight-second body-read deadline, and the two QR workers bound decoding and rendering. Responses contain only rendered pixels or generated SVG geometry. The service ignores text and color profile data in the upload and retains the logo only for the request.
- Audit the action, authorized actor, object ID, time, and outcome. Use a log field allowlist and omit query strings, passwords, keys, cookies, full IP addresses, header dumps, and full destination URLs from runtime diagnostics. Protect access to audit records and exports independently. Apply equivalent logging controls to the reverse proxy at installation. [OWASP Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)
- Review dependency and operating system advisories, licenses, Cargo and JavaScript feature lists, and base image digests before release. Use lockfiles, reproducible build steps, artifact verification, and minimal CI credentials. Apply the same checks to automated dependency updates.

## Implemented title lookup policy

Title lookup is off by default. Turning it on in Settings › Operations, or `TITLE_LOOKUP_ENABLED=true` while nothing is saved there, lets administrators request page titles for untitled links. Turning it off stops further requests at once; a lookup that already started finishes, and its result is applied only if the link still matches. Adding password or one-time protection cancels a pending lookup, and the worker skips protected links. Link monitor enrollment does not check protection, so do not enroll protected destinations. Requests use the same public address policy as health probes: validated HTTP on port 80 or HTTPS on port 443, DNS answers pinned to public addresses, a new validation for each of at most three redirects, no proxies, no cookies, no referrer, identity encoding, and TLS verification. A lookup reads at most 128 KiB within eight seconds and stores only plain text of up to 160 characters, which the interface renders as text. Links with password or one-time protection are not fetched, because the destination itself might treat the request as a use. The destination policy is checked before any connection. The worker is independent of the public listener and never runs during a redirect.

## Implemented preview image policy

Preview images are off by default and need title lookup as well: **Fetch preview images** in Settings › Operations, or `PREVIEW_IMAGES_ENABLED=true` while nothing is saved there. Turning on the switch while title lookup is off is refused with `title_lookup_required`, and turning title lookup off pauses previews. The image URL comes from the same page response the title lookup reads (`og:image`, `twitter:image`, then the page icon and `/favicon.ico`), so a preview adds no page request. No page is rendered and no script or headless browser runs.

Every image request is a new outgoing request and gets the full public policy again: only `http` and `https` URLs, resolved against the final page URL, validated port 80 or 443, DNS answers pinned to public addresses, no credentials in the URL, no proxies, cookies, or referrer, identity encoding, a new validation for each of at most three redirects, and the destination policy for the image URL. Private, loopback, link-local, and documentation addresses are refused before connecting, also after a redirect. A response must be a raster image type other than SVG and at most 2 MiB, read within eight seconds; at most three image requests are sent per preview. The fetcher's four shared permits bound concurrency with health probes and webhooks, and one worker handles one link at a time, two seconds apart.

The bytes are untrusted input to an image parser. Only the pure-Rust PNG, JPEG, WebP, and GIF decoders of the `image` crate are compiled in (no SVG, AVIF, TIFF, BMP, or other formats, no C libraries, and no thread pool); an ICO file is accepted only through its embedded PNG. The format is chosen from the leading bytes, not from `Content-Type`. Decoding runs on a blocking thread with at most 4,096 pixels per side and 64 MiB for the decoded image, which refuses decompression bombs before their pixels are allocated. GIF and animated WebP decode their first frame only. The result is resized to at most 480 × 270 (icons 64 × 64), flattened, and re-encoded as a baseline JFIF JPEG of at most 48 KiB, so no original bytes, EXIF, XMP, ICC profiles, or comments are stored. Only the image URL's origin is kept.

`GET /api/v1/links/{id}/preview` serves only those stored bytes, from the admin origin, as `image/jpeg` with `X-Content-Type-Options: nosniff`, `Cross-Origin-Resource-Policy: same-origin`, `Cache-Control: private, max-age=3600`, and the admin CSP. The interface shows it with `img-src 'self'` and needs no `data:` URLs. Browser sessions and `read` keys within their host may fetch it; refreshing is browser-session only. Password and one-time links are never fetched, adding protection deletes their preview, and a changed destination clears it. Verified snapshots drop the saved switch, and a restore drops pending fetches. Restored thumbnails are served as stored, with the same headers.

## Implemented outbound monitoring policy

Health checks are off by default. An administrator turns them on in Settings › Operations; `MONITOR_ENABLED=true` remains a start value that applies while nothing is saved there. Only then can an administrator enroll a saved link or check a saved public domain. The setting applies without a restart: turning health checks off stops new probes and refuses manual checks and new enrollments at once, and turning them on wakes the scheduler. A changed destination removes its enrollment. The public listener only resolves a stored destination. It never performs probes. A probe that has already started can finish after enrollment is withdrawn. Its result is discarded if the enrollment was removed or replaced.

Health probes use a client restricted to validated HTTP destinations on port 80 and HTTPS destinations on port 443. The resolver rejects nonpublic addresses and DNS answers containing any blocked address. The connection can use only the validated addresses, including after a redirect. Each hop establishes a new validation context. Health checks allow at most three redirects and use HEAD with a bounded GET probe when the destination rejects HEAD. Requests discard response bodies. TLS hostname and certificate verification remain enabled.

Confirmed link-health transitions are delivered as `link_health` notifications. See [Notifications and internal connectors](#notifications-and-internal-connectors). `MONITOR_WEBHOOK_URL` and `MONITOR_WEBHOOK_URL_FILE` remain aliases for the notification webhook that select only `link_health` events. Choose enrolled links deliberately because the destination receives the stored path and query during checks. Avoid enrolling signed, one-use, and sensitive destinations when the probe itself could consume or disclose their contents.

The scheduler serializes probes. Stable links target a 24-hour interval and priority links a 6-hour interval by default, plus deterministic jitter. Adjust them in Settings › Operations, or with `MONITOR_INTERVAL_HOURS` and `MONITOR_PRIORITY_HOURS` as start values. A shorter interval moves later checks forward; a longer one applies after each link's next check. Attempts to slow destinations and backlogs can delay checks. Paused, archived, expired, and future links are skipped during scheduled runs. Exact destinations share a probe when they are in the same batch. Spaced checks and a capped retry backoff limit traffic.

## Destination policy

An administrator can enable a destination policy with allow and block rules for destination hosts. A matching block rule always wins. When allow rules exist, a destination must match one. Hosts are compared in lowercase IDNA form without a trailing dot, using the URL parser's host so mixed case, percent-encoded names, numeric IPv4 spellings, and IPv4-mapped IPv6 literals cannot bypass a rule. A host with an empty label cannot be compared and is refused while the policy is enabled. Write paths reject new refused destinations. The public redirect path enforces the policy on the destination it selects before it offers a protected-link confirmation or reserves a visit, so a refused redirect consumes no allowance or one-time access. The policy uses a process-local copy that the redirect query invalidates through a stored generation number. It performs no outbound request. Policy changes are recorded in the audit log. The unusual-traffic report is a separate, informational indicator that never changes a link.

## Public pages

Since 0.9.0 an administrator can replace the missing-link, unknown-host, password, and one-time pages per language in Settings > Public pages. This is administrator-authored content served on the public hosts, so it crosses the boundary from the admin listener to every visitor. The controls:

- **Who can change it.** Only a browser administrator session with Origin and CSRF. API keys are refused, including for reads. Saves, resets, and imports are audited as `public_pages_update`, `public_pages_reset`, and `public_pages_import`, and produce a security notification when notifications are enabled.
- **Structured mode** writes plain text, a validated `#rrggbb` accent, and an optional PNG, JPEG, or WebP logo of at most 64 KiB into the built-in layout. Text is HTML-escaped. The logo's file signature must match its type. SVG is refused, because it can carry scripts and external references. The logo is inlined as a `data:` URI rather than served from a public path: a fixed path would shadow a slug on every domain and would need `img-src 'self'`, while `img-src data:` allows no network load at all.
- **Custom HTML** passes an allowlist sanitizer on save and again whenever the public listener loads it, so a row written around the API cannot add markup. ShortCircuit uses its own minimal sanitizer instead of adding an HTML parsing dependency tree: it tokenizes the input and writes a new document from allowlisted elements and attributes with escaped text and attribute values, so the browser only parses markup the sanitizer produced. It removes scripts, event handlers, `style` attributes, `javascript:` and every URL other than HTTP, HTTPS, relative links, and inline PNG, JPEG, or WebP images, iframes, objects, embeds, forms and inputs, `meta` (including `http-equiv` refreshes), `link`, `base`, and SVG. Style sheets with imports, remote or non-raster `url()` values, CSS escapes, legacy script hooks, or `<` are refused. Pages are limited to 64 KiB.
- **Content Security Policy.** Customized pages send `default-src 'none'; style-src <sha256 of each style element>; img-src data:; form-action 'self'; base-uri 'none'; frame-ancestors 'none'`. There is no `script-src`, so scripts cannot run even if the sanitizer missed one. Styles are allowed by hash, not `'unsafe-inline'`, which is why `style` attributes are removed. Built-in pages keep their previous policy.
- **Form mechanics stay server-side.** Password and one-time pages must contain `{{form}}` exactly once, and the server inserts its own form there. The signed challenge, Origin check, password verification, rate limits, `303` response, and `Referrer-Policy: strict-origin` are unchanged. Placeholders are HTML-escaped and never include the request path or slug. A missing path and an inactive link still receive byte-identical responses.
- **Availability.** The public listener keeps compiled pages in memory and rereads the table only after a change in the same process. Rendering cannot fail a request: an entry that does not validate falls back to the built-in page, and a read error keeps the previous pages and retries after five seconds.
- **Preview.** The admin interface frames a server-rendered draft in an `<iframe sandbox>` without `allow-scripts`, `allow-same-origin`, or `allow-forms`. The preview response carries the public page's policy with `frame-ancestors 'self'` and `X-Frame-Options: SAMEORIGIN`, so other origins cannot frame it, and it requires the admin session.
- **Phishing risk.** A custom page can imitate a sign-in or payment page, link to any HTTP or HTTPS site, and inline images, on your own short-link domain. The sanitizer and CSP stop scripts, credential forms posting elsewhere, external loads, and redirects, but not deceptive text. Import template files only from sources you trust, check every page in the import preview, and keep the built-in password and one-time pages if you do not need a custom design. A compromised admin session can change what every visitor sees, so treat these audit entries as security events.

## Notifications and internal connectors

Notifications are off until a webhook is set in Settings › Operations, or `NOTIFICATION_WEBHOOK_URL` or a read-only `NOTIFICATION_WEBHOOK_URL_FILE` names an HTTPS endpoint while nothing is saved there. Without a connector, delivery uses the public outbound policy: port 443, DNS answers pinned to public addresses, TLS verification, no proxy, and no redirects. Each delivery posts a small JSON object with `version`, a stable `id`, `event`, `occurred_at`, and numeric fields such as `link_id`, `expires_at`, `milestone`, or `audit_id`. Payloads never contain destination URLs, slugs, hostnames of links, titles, visitor data, or credentials. Deliveries are at least once. A receiver should ignore a repeated `id`.

An internal receiver is reachable only through one explicitly configured connector. `NOTIFICATION_CONNECTOR_ORIGIN` pins one bare HTTPS origin, which the webhook URL must use, and `NOTIFICATION_CONNECTOR_NETWORKS` lists up to 16 CIDR ranges that every resolved address must fall into. Loopback, link-local, unspecified, and multicast addresses are always refused, and ranges broader than `/8` for IPv4 or `/16` for IPv6 are rejected at startup. `NOTIFICATION_CONNECTOR_CA_FILE` can add PEM roots for a private CA. Certificate verification is never disabled. The connector applies only to webhook delivery. Health probes, title lookups, and preview images keep the public policy, and there is no global override. `NOTIFICATION_WEBHOOK_AUTHORIZATION_FILE` supplies an `Authorization` header value that is sent only to the configured webhook URL, is marked sensitive, and is never shown in the interface. Because redirects are never followed, the header cannot be forwarded to another host.

The webhook URL and the header can also be saved in Settings › Operations. Both are write-only: the API and the interface report only whether they are set and the webhook's scheme, host, and port, never its path, query, or the header value, because a Slack- or Discord-style URL carries its secret in the path. Setting, clearing, or resetting either one requires the current password through a one-use, two-minute grant bound to the browser session, limited by `RATE_LIMIT_SENSITIVE`. A saved URL passes the same validation as the container value: HTTPS, port 443 without a connector or the exact connector origin with one, no credentials, and a valid header value. A literal non-public address is refused when it is entered, as delivery would refuse it anyway, and names are still resolved and pinned on each delivery. A changed webhook discards pending deliveries and starts event detection afresh, so the new target never receives earlier history. Every change of an operations setting is audited by setting name without values and produces a `security` notification. The connector variables stay environment-only, so an administrator session cannot widen the networks a webhook may reach.

The database stores a saved webhook URL and header in plain text, like the rest of its data, so protect the data volume. Verified snapshots remove them, together with the saved health check, title lookup, and preview image switches: backups leave the host and are downloaded through browsers, and a restored installation must not start outgoing requests that its own administrator did not turn on. After a restore, those five settings follow the restoring installation's container values until an administrator saves them again. Intervals, retention, and the event selection are kept.

The outbox stores each event under a deterministic key, so detection after a restart does not create a second delivery. Failed deliveries are retried after 1, 2, 4, and up to 60 minutes, at most eight times. A delivery refused by the address policy fails immediately. Rows that remain undelivered for 24 hours are marked stale. After a restore, pending rows are discarded, and events older than the restore are not generated again. The latest 1,000 settled rows are kept.

## Client addresses and request limits

Configure `TRUSTED_PROXIES` as a comma-separated list of individual IP addresses or CIDR networks for actual proxy peers. The empty default uses the TCP peer. ShortCircuit uses one bounded `X-Forwarded-For` chain from a trusted peer and walks it right to left to the first untrusted address. Malformed or ambiguous inputs use the direct TCP peer. Forwarded host and scheme headers do not set either listener's trusted origin.

IPv6 clients share one per-peer budget per /64 prefix. Public `429` responses include `Retry-After: 60`. A protected-link password attempt must fit four budgets at once: the client's and the process-wide budget from `RATE_LIMIT_PUBLIC_PASSWORD`, and the client's budget for that link and the link's ceiling across all clients from `RATE_LIMIT_PUBLIC_PASSWORD_LINK`. The client key is the same address or /64 prefix that `TRUSTED_PROXIES` resolves. The default link ceiling of 30 stays below the process-wide 60, so guessing one link's password leaves attempts for every other link, and a distributed attempt on one link is bounded to 30 per minute. A flood against one link can still delay its correct password until the window ends. Only counted attempts create counter entries, so each counter map holds at most the process-wide count per window and is cleared when the window ends. A refused attempt counts toward no budget and returns before any password lookup or verification. Budgets do not change one-time consumption or visit limits. The variables below use `per-peer,global` counts per minute. A blank variable selects the default. Budget exhaustion returns HTTP 429.

| Variable | Default | Scope |
|---|---:|---|
| `RATE_LIMIT_LOGIN` | `8,60` | Account setup, sign-in, and recovery |
| `RATE_LIMIT_SENSITIVE` | `8,60` | Password changes, key rotation, and browser backup and restore authorization |
| `RATE_LIMIT_API` | `240,4000` | Admin API, including session status |
| `RATE_LIMIT_PUBLIC_PASSWORD` | `8,60` | Protected-link password attempts per client and per process, across all links |
| `RATE_LIMIT_PUBLIC_PASSWORD_LINK` | `5,30` | Protected-link password attempts per client and link, and per link across all clients |
| `RATE_LIMIT_PUBLIC` | Off | Optional combined public listener limit, including lookup misses |

**System**, **Backups** lists stored snapshots and restore rollback copies for browser sessions only (`GET /api/v1/system/backups`). The list is read-only, names files without paths, skips symbolic links and unexpected names, and reads the schema version with a read-only, immutable SQLite connection with `trusted_schema=OFF`. Stored files cannot be downloaded through the API, because a raw rollback copy still contains the session and setup digests that verified snapshots remove. Import problems name the failing row and field but never echo submitted values.

The latest 1,000 administrative audit entries are available in **Audit log**. Account actions, key changes, monitor enrollment, and browser backup and restore events use fixed action identifiers and numeric object IDs. A domain deletion records its public host, the link action (`move`, `delete`, or `none`), the target host, and the link count in the entry's `details`. Deleting a domain requires a browser session and, when links are deleted, the typed host name. It is refused while unexpired API keys are restricted to a host outside `PUBLIC_HOSTS`, so re-adding the host later cannot revive a forgotten key. Audit entries exclude credentials, destination URLs, visitor addresses, and request headers.
